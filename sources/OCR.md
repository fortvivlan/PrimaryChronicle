# Распознавание сканов

Оригиналы в `data/texts/` не изменяются. Автоматические результаты находятся
в **`data/ocr/`**, отдельно от ручной разметки ПВЛ и данных демонстрации.
План обработки — [ocr-plan.json](ocr-plan.json), модели с фиксированными
версиями и SHA-256 — [ocr-models.json](ocr-models.json).
Сводка обработки без распознанных текстов — [ocr-report.json](ocr-report.json).

`review_status: unreviewed` и `eligible_for_linguistic_analysis: false`
означают, что результат ещё нельзя использовать как проверенный текст.
Успешное выполнение OCR или проверки хешей этого статуса не меняет.

## Установка и запуск печатного OCR

Нужны Python, Tesseract 5, DjVuLibre (для РИБ), PyMuPDF и Pillow.
Пример для Debian/Ubuntu:

```bash
sudo apt install tesseract-ocr djvulibre-bin python3-venv
python3 -m venv data/ocr/tools/venv
data/ocr/tools/venv/bin/pip install -r scripts/requirements-ocr.txt
python3 scripts/download_ocr_models.py
data/ocr/tools/venv/bin/python scripts/ocr_sources.py --list
data/ocr/tools/venv/bin/python scripts/ocr_sources.py \
  --only pchela-1893 josephus-1958 kirik-2011 kirik-rib6 --jobs 8
```

В текущем локальном окружении зависимости также могут лежать в
`data/ocr/tools/python`, а извлечённые Linux-инструменты — в
`data/ocr/tools/native`. Скрипт обнаруживает их автоматически. Их не нужно
копировать в системные каталоги. Один процесс Tesseract использует один
поток; `--jobs` задаёт число независимых процессов обработки страниц.

Для пилота или повторной обработки конкретной страницы:

```bash
python3 scripts/ocr_sources.py --only josephus-1958 --pages 172-175 --jobs 4
python3 scripts/ocr_sources.py --only kirik-2011 --pages 358 --languages orus
```

Номера в `--pages` — **физические страницы файла, начиная с 1**.
Для изображений это позиции в сохранённом манифесте. Это не печатная
пагинация и не номера листов рукописи. Например, изображение Андрея
`0212.jpg` — вторая позиция в манифесте, а не страница 212.
Печатные и физические номера нельзя связывать одним постоянным смещением:
в PDF Флавия смещение меняется внутри книги.

Печатные задания охватывают издания целиком, включая исследования и
аппарат; исключение — посторонний № 5 в составе тома «Пчелы».
План помечает предполагаемые разделы древнерусского текста, но не выдаёт
их за уже отделённый основной текст. У «Пчелы» изображения 75–518 содержат
параллельные славянский и греческий тексты; 519–520 завершают № 4.
Изображения 521–600 исключены. У Флавия основной текст расположен на
физических страницах 172–476 (печатные 167–467).

## Результаты и возобновление

Каждый набор источников, моделей, параметров, версий библиотек и алгоритма
получает свой каталог `data/ocr/<задание>/<отпечаток>/`.
Другие варианты распознавания не заменяют прежние результаты.
`latest.json` указывает на последний запущенный вариант, который может
быть ещё неполным. Пилот не считается обработкой всего издания.

Для каждой страницы сохраняются:

- `pages/NNNN.txt` — исходный результат OCR без исправления орфографии;
- `NNNN.tsv` и `NNNN.hocr` — слова, координаты и оценки уверенности;
- `NNNN.preview.jpg` — производное изображение для сверки с координатами;
- `NNNN.embedded.txt` — прежний текстовый слой PDF/DjVu, если он есть;
- `NNNN.log` — сообщения движка;
- `NNNN.json` — источник, страница, параметры изображения, статистика,
  статус и контрольные суммы всех файлов результата.

Координаты относятся к растру OCR, начало — в левом верхнем углу.
Размер исходного и обработанного растра записан отдельно. PDF/DjVu
визуализируются при 300 dpi. Небольшие JPEG «Пчелы» увеличиваются вдвое;
это не восстанавливает утраченные детали. Применяется только автоконтраст,
без стирания помет и надстрочных знаков. JPEG-превью служит для просмотра;
распознавание проводится по временному PNG.

`run.json` содержит ожидаемые и завершённые страницы и ошибки.
`review.csv` позволяет найти страницы с низкой уверенностью;
`text.txt` объединяет только готовые страницы с явными разделителями.
Эти два файла — производные указатели, их можно пересоздать повторным запуском.
Пустая страница остаётся страницей, а не исчезает из нумерации.

Повторный запуск проверяет контрольные суммы результатов и пропускает
только полностью сохранённые страницы с тем же отпечатком. Повреждённый
производный результат восстанавливается; изменённый оригинал вызывает
ошибку. После аварийного завершения может остаться `.lock`: перед его
удалением нужно убедиться, что процесс этого задания уже не работает.

```bash
python3 scripts/download_ocr_models.py --verify
python3 scripts/ocr_sources.py --verify \
  --only pchela-1893 josephus-1958 kirik-2011 kirik-rib6
python3 scripts/download_sources.py --verify
```

Проверка OCR работает без сети и без распознающих библиотек. Она проверяет
полноту, модели, оригиналы, извлечённый DjVu и файлы каждой страницы.
Она **не оценивает правильность прочтения**. Средняя уверенность Tesseract
также не является измерением точности или CER.

## Ограничения и вычитка

Для исторической кириллицы добавлен отдельный движок Kraken 7.1.1.
Он использует нейросетевую сегментацию строк `blla` и модель
[PP-OCRv6 medium, Benjamin Kiessling](https://zenodo.org/records/21788410),
в обучение которой включены церковнославянские данные. Это общая модель,
а не специально обученная транскрипция наших списков. В локальных пробах
модель [small](https://zenodo.org/records/21788405) сохраняет исторические буквы
заметно лучше, чем `tiny`; `medium` даёт более аккуратные отдельные
чтения. Для CUDA по умолчанию выбран `medium`, для CPU — `small`. Это выбор модели
для чернового распознавания, а не измеренная оценка точности корпуса.
Для сравнения также
сохранена модель [Cyr02, A. Rabus, W. R. Thompson, D. Stökl Ben Ezra](https://zenodo.org/records/7755483)
(CC BY 2.0). Файлы обеих моделей и сегментатора проверяются по SHA-256.

Kraken требует Python 3.10–3.13; системный Python 3.14 для него не подходит.
Пример отдельного окружения с CPU-версиями PyTorch:

```bash
python3.13 -m venv data/ocr/tools/htr-venv
data/ocr/tools/htr-venv/bin/pip install \
  'torch==2.9.1+cpu' 'torchvision==0.24.1+cpu' \
  --index-url https://download.pytorch.org/whl/cpu
data/ocr/tools/htr-venv/bin/pip install -r scripts/requirements-htr.txt
python3 scripts/download_ocr_models.py
data/ocr/tools/htr-venv/bin/python scripts/htr_sources.py --only andrew-egor162
data/ocr/tools/htr-venv/bin/python scripts/htr_sources.py --only kirik-2011
data/ocr/tools/htr-venv/bin/python scripts/htr_sources.py --only pchela-1893
```

В Windows можно использовать CUDA из базового Python, установив остальные
зависимости в отдельное окружение проекта. Следующие команды PowerShell
не заменяют уже установленный CUDA PyTorch:

```powershell
python -m venv --system-site-packages data/ocr/tools/htr-windows
data/ocr/tools/htr-windows/Scripts/python.exe -m pip install -r scripts/requirements-htr.txt
data/ocr/tools/htr-windows/Scripts/python.exe -c "import torch; print(torch.__version__, torch.cuda.is_available(), torch.cuda.get_device_name(0))"
data/ocr/tools/htr-windows/Scripts/python.exe -X utf8 scripts/htr_sources.py --only andrew-egor162 --device cuda:0 --batch-size 16 --threads 4 --jobs 2
data/ocr/tools/htr-windows/Scripts/python.exe -X utf8 scripts/htr_sources.py --only kirik-2011 --device cuda:0 --batch-size 16 --threads 4
data/ocr/tools/htr-windows/Scripts/python.exe -X utf8 scripts/htr_sources.py --only pchela-1893 --device cuda:0 --batch-size 16 --threads 4 --jobs 3
```

CUDA используется и сегментатором, и распознавателем; автоматического
перехода на CPU нет. По умолчанию один процесс хранит модели в памяти GPU;
`--jobs` позволяет запустить несколько процессов, каждый со своей копией
моделей. В локальном запуске используется RTX 4090 с 24 ГБ VRAM:
три процесса «Пчелы» одновременно с двумя процессами Андрея и одним Кирика.
Неиспользуемые временные GPU-буферы освобождаются после предсказаний,
чтобы процессы не удерживали одновременно пиковые объёмы памяти.
Проверенное Windows-окружение: Python 3.12.10, PyTorch 2.14.0+cu132,
torchvision 0.29.0+cu132, Kraken 7.1.1.
`--batch-size` задаёт число строк в пакете, а `--threads` — потоки CPU для
сопутствующей обработки. Устройство, GPU, версии CUDA/cuDNN и размер пакета
включены в отпечаток запуска. Первые CPU-варианты сохраняются отдельно.
Относительные пути оригиналов и моделей позволяют проверять Windows-результат
командой `--verify` также из Linux без установки CUDA.

Полная область HTR: все 136 фотографий Андрея; у Кирика — страницы 312–341,
358–412, 474–534; у «Пчелы» — изображения 75–518. `--pages` задаёт пилот,
а не меняет ожидаемый объём задания. Для сравнения с другой моделью:

```bash
data/ocr/tools/htr-venv/bin/python scripts/htr_sources.py \
  --only andrew-egor162 --pages 2 --model data/ocr/models/Cyr02full_best.mlmodel
```

HTR сохраняется в `data/ocr/htr/<задание>/<отпечаток>/`, отдельно от Tesseract.
Для каждой страницы сохраняются текст, ALTO XML с геометрией строк,
`NNNN.lines.json` с базовыми линиями, границами и посимвольными уверенностями,
превью и JSON с происхождением и хешами. Изображение ограничивается шириной
4000 пикселей; исходный размер записывается отдельно. При ошибке топологии
сегментатора страница повторяется при 90% и затем 80% этого размера;
неудачные попытки записываются в `segmentation_warnings`. Если все строгие
попытки неуспешны, сохраняются доступные строки с явной пометой
`partial_segmentation: true`: такие страницы требуют ручной сегментации.
Если и частичное распознавание не удалось, страница остаётся незавершённой.
Масштаб и координаты сохранённого
результата всегда соответствуют его превью. Порядок строк и
колонок определяет модель: он тоже требует проверки. Посимвольные оценки
Kraken и оценки слов Tesseract нельзя напрямую сравнивать как точность.
Отсутствие распознанных слов не подтверждает, что лист пуст. Например,
на фотографии Андрея в позиции 135 модель не прочла карандашные пометы:
эта страница остаётся для ручной проверки. Просмотрщик явно отмечает
такие результаты как `NO TEXT RECOGNIZED`.

```bash
python3 scripts/htr_sources.py --only andrew-egor162 --verify
python3 scripts/ocr_report.py --export sources/ocr-report.json
python3 -m http.server 8001 --directory data/ocr
```

Локальная страница <http://localhost:8001/review.html> показывает превью и
сырой текст рядом. Это просмотр для сверки, он не утверждает чтения и
не меняет статусы. Отчёт в Git содержит только сведения об обработке,
без полных распознанных текстов. Он отражает состояние на момент экспорта;
актуальные локальные результаты можно пересчитать той же командой.

Команда для запуска сервера:

```python3 -m http.server 8001 --bind 127.0.0.1 --directory data/ocr```

Модель [orus](https://github.com/AButon-8/iskra_ocr) обучена на дореформенном
гражданском шрифте «Искры». Она позволяет распознавать ѣ и і, но её алфавит
и шрифты не покрывают средневековую кириллицу. Модели `rus` и `grc` взяты
из [tessdata_best](https://github.com/tesseract-ocr/tessdata_best).
Смешанный запуск на славянском и греческом тексте может путать похожие
буквы разных алфавитов. Особенно ненадёжны церковнославянский шрифт Кирика,
титла, выносные буквы и древние буквы «Пчелы».

Фотографии Андрея (136 разворотов) и фототипия Кирика, с. 335–341,
требуют HTR. Наличие печатного OCR этих страниц не делает их транскрипцией.
Для них нужно проверять сегментацию строк, порядок колонок, инициалы,
выносные буквы и повреждения. Нечитаемые места нельзя заполнять по смыслу
или по другому списку без явной фиксации редакторского вмешательства.

До импорта в корпус необходимо отделить основной текст от вариантов,
греческих параллелей, переводов, заголовков и примечаний; проверить
исторические буквы и надстрочные знаки; затем сверить текст со сканом.
Исправления и ручные транскрипции следует сохранять отдельно от сырого
OCR, со ссылкой на страницу/строку и с указанием проверившего.
HTML-тексты Изборника и Манускрипта не подвергаются OCR: им нужна
проверяемая конверсия шрифтовых кодировок, описанная в [README.md](README.md).
